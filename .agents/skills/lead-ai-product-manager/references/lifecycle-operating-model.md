# Lifecycle Operating Model

## Lifecycle

### 1. Opportunity

Establish the target customer, customer journey, painful/frequent problem, alternatives, team advantage, risks, and falsifiable problem hypothesis.

Exit with traceable problem evidence. A research gap can authorize only bounded exploration through a waiver; it cannot become evidence.

### 2. Direction

Define the product vision, business and behavior flow, user/buyer distinction, viability/economics, adoption needs, objective, key results, scope, non-goals, constraints, and AI risk posture.

Exit with strategic boundaries and measurable outcomes, not a committed feature list.

### 3. Options roadmap

Maintain one option repository. Define context-specific factors, identify one to three critical decisions, gather constrained stakeholder input, rank hypotheses, and allocate validation capacity. State what evidence each option must earn before implementation commitment.

### 4. Concept validation

Test solution desirability, usability, feasibility, and AI/data/model assumptions with representative users/tasks and explicit success, failure, and stop criteria. Record severity, limitations, and learning sufficiency.

Exit with a proceed, pivot, hold, or stop decision from an accountable owner.

### 5. Committed delivery

Translate validated scope into traceable, small backlog items with acceptance criteria, owners, dependencies, risks, implementation evidence, and pre-launch instrumentation. Keep objective → requirement → implementation → verification traceability.

### 6. Launch

Use independent evidence for go/no-go. Verify functional, safety, security, privacy, accessibility, performance, AI evaluation, observability, support, rollout, rollback, and unresolved-severity thresholds. Define adoption and change plans.

### 7. Operate and measure

Operate service and model controls, observe the defined window, maintain incidents/escalations, validate data quality, and interpret metrics and experiments with causal limits.

### 8. Iterate or sunset

Recommend roadmap changes from evidence. Return to an earlier phase when assumptions fail. Sunset with customer migration, data/legal obligations, communications, support, shutdown verification, and accountable approval.

## Cadence

- **On update:** reconcile changed facts, assumptions, risks, dependencies, and decisions.
- **Weekly:** assess gate health, critical path, evidence freshness, and one priority action.
- **Before commitment:** verify prerequisites and decision authority.
- **Before launch:** run launch-readiness and authorization checks.
- **After launch:** observe the predefined window before drawing outcome conclusions.
- **Quarterly:** revisit objectives, KRs, options, investment allocation, and lifecycle stage.

The cadence never authorizes a write or external action by itself.
